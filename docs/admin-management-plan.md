# 个人网站后台：需求与实施计划

目标：解决个人网站没有管理后台的问题；第一版只做后台框架和基本功能。

状态（2026-10-25）：任务1—7已验收，整体7/8。阶段F本地交付及非HTTPS服务器配套已完成；用户本轮明确授权独立迁移生产数据库，现001—003全部应用、12张表/10项默认工具验证通过，无待迁移项；迁移前及迁移后快照均在Mac加密保存并从解密内容恢复通过。current保持f01d1fe，未创建管理员/导入内容/合并发布。HTTPS、持续异机备份、生产内容及整体验收仍未完成。

## 已确认需求

| 模块 | 第一版范围 |
|---|---|
| 管理员登录 | 单管理员本人使用，不开放注册。 |
| 项目管理 | 名称、简介、技术栈、图文详情、封面、截图、在线体验和源码链接；新增、修改、草稿、预览、发布、下架、展示排序；日常维护不用改代码。 |
| 访问统计 | 仅网站访问人数、各项目浏览人数。 |
| 网站内容设置 | 姓名、头像、个人简介、联系方式、社交账号链接。 |
| 小工具管理 | 九宫格工具是否展示、展示顺序；左下角独立骰子是否展示。 |

使用 PostgreSQL 持久化数据；沿用现有 Vue 3 + Vite、FastAPI、测试和发布流程。不增加多用户、角色权限、审批、内容历史版本、来源/点击统计、独立素材库、反馈或复杂监控，也不开发新工具。

## 已确认行为

- 环境配置：用户确认采用一个统一配置模块、本地 .env 与服务器外部 app.env 的简化方案；本次先实现本地配置和模块，生产仅提供操作步骤，不修改服务器。
- 数据库部署：按用户最新选择，开发库和生产库均放在云服务器，本地数据库不作为开发前提；自动化测试使用自建并清理的临时本地 PostgreSQL 集群，与共享开发库隔离，具体用法见 README。

- 项目保存与发布：新项目按“草稿 → 预览 → 发布”操作；草稿允许内容不完整，发布前校验必要内容。已发布项目修改后可先预览，未保存的编辑和预览不影响前台；点击“保存并更新”且保存成功后立即生效。校验或保存失败时保留原公开内容，第一版不维护独立的待发布内容副本。
- 访问人数：使用匿名浏览器标识，同一浏览器在所选时间范围内只计 1 人；首页访问计入网站人数，打开已发布项目详情才计入该项目浏览人数，不把卡片展示计入。提供近 7 天、近 30 天，排除管理员访问和后台预览；区间总人数独立去重，不能直接累加每日人数。浏览器标识只能近似人数，无法补录启用前的访问。

### 数据库与图片成套备份、恢复

助手建议每天一次完整备份、每次迁移前额外一次；日备份保留 7 份、周备份保留 4 份，迁移前备份至少保留到该次发布验收与回退窗口关闭。建议恢复点目标为最近一次成功备份（常规最多约 24 小时数据损失），恢复时间暂定 2 小时，须经数据规模和恢复演练确认。失败备份报警给维护者，不覆盖最近有效备份；备份失败时停止后续迁移。

获生产授权且备份工具落实后，按以下顺序执行；这不是当前可直接执行的生产脚本。日常独立备份自行取得发布互斥锁，与发布互斥；迁移前备份由已持锁的发布流程内嵌调用，只归档和检查，不重复取同一锁，不要求发布流程退出，也不自行重启服务或解除写控，其生命周期由下节发布流程负责：

1. 日常独立备份先暂停自动发布、取得发布互斥锁并确认无其他部署/迁移运行；迁移前备份复用发布方的锁及停写窗口。停写覆盖所有业务写入、图片变更和访问统计。最简单的初版建议为短时停止两个 worker 所属服务，在窗口内返回维护响应；仅隐藏后台按钮不算停写。数据库或其他写入者也必须停止。
2. 使用有备份权限的账号对明确的生产库执行 `pg_dump --format=custom`，归档同一停写窗口内的整个 uploads；数据库连接凭据由权限受控的认证文件或交互取得，不放命令、Git 或日志。使用兼容的 PostgreSQL 客户端，不直接打包运行中数据库的数据目录。
3. 为这一组文件记录 UTC 时间、数据库身份、迁移版本/校验和、应用提交、图片文件数量和归档 SHA-256。执行 `pg_restore --list`、归档可读性及校验和检查；以上检查只证明文件可读，不代替恢复演练。日常备份成功或失败后，外层流程均须重启旧服务并检查健康，成功后才解除写控；恢复失败保持维护响应并交人工处理。迁移前备份不得在此解除写控，继续迁移和发布验收。
4. 加密复制整组备份至异机目的地，核对副本校验和；确认成功后执行保留策略，失败则保留旧有效组并报告。日常任务与发布彼此互斥；迁移前备份属于发布内部步骤，不能嵌套调用会再次取锁的独立备份入口。异机复制完成前不执行迁移；独立备份可在恢复服务后继续持锁完成复制，最后释放锁。
5. 恢复时先在独立临时库和临时图片目录演练，核对目标身份，绝不覆盖共享开发库或直接试恢复生产库。准备备份记录对应的应用与配置；使用 `pg_restore` 恢复到空库，并按文件校验恢复图片和属主权限。数据库角色/权限须预先准备，单库 dump 不包含集群角色。
6. 验收表数据和迁移版本、关键内容及图片引用一致，无缺失文件；用同一应用版本验证公开内容、管理员登录/预览、草稿不可匿名读取、已下架图片权限、排序和统计查询。记录实际耗时及丢失时间范围。成功后清理演练资源；真实恢复另需生产授权：先取得同一发布互斥锁、暂停发布并建立覆盖所有写入者的停写窗口，再成套备份现场数据库与图片并验证可恢复；现场组失败则不切换。然后切换已验证的数据与图片、启动对应应用并验收；失败时保留故障现场，按现场成套组回切并验证旧应用健康。恢复验收或回切验收成功前始终维持写控，成功后才解除写控并释放锁；两者均失败则保持维护响应，保留恢复材料并交人工处理。

### 迁移、发布与回退顺序

现有 [部署入口](../scripts/deploy.py) 先持有 `deploy.lock`、验证旧版本健康、核对目标为 main HEAD、安装锁定依赖并构建新 release，再次核对 HEAD 后切换 `current`、重启并验证 API/首页/资源/提交标记；失败尝试切回旧链接并重启，发布仍报失败。[CI](../.github/workflows/ci.yml) 要求检查成功、main 及相应发布开关，并用 production 并发组串行发布。服务器入口是 `/usr/local/lib/personal-web/deploy.py`，仓库脚本变更不会自动替换它。上述是代码静态事实，本轮没有重验线上部署行为。

`prepare()` 的 Gunicorn `--check-config` 继承 SSH 进程环境，不会自动读取 systemd 的 `/etc/personal-web/app.env`；它不是生产配置加载验收。任务 1 新增数据库初始化时须保证导入/构建检查不连接或迁移生产库；8B 在不泄露凭据的前提下确定检查所用隔离配置，并单独验证真实 systemd 启动。不能因用户已完成 app.env 接入就假设 SSH 构建环境也具备生产配置。

现有入口没有数据库迁移和图片恢复步骤，自动回退只恢复应用链接。任务 1 的 `apply_dev.sql` 仅面向开发库，不得当作生产入口。8B 需在现有发布保护内增补独立、串行的生产迁移步骤或受同一互斥保护的操作流程；不能先手工改库再让自动部署无条件发布，也不能绕过 main/HEAD、启用开关和检查。

1. 发布前固定目标提交、旧版本和 schema 版本，确认新旧应用均兼容迁移后的 schema，并在隔离库验证迁移失败回滚、重复执行及旧应用读取。任务 1 交付生产身份保护、迁移版本/校验和、事务与锁契约后才能落实。双 worker 各自按需建立连接；如未来增加连接池，各进程独立初始化。不能在 Gunicorn 导入、worker 启动或请求中自动迁移。
2. 发布外层流程一次取得 `deploy.lock`，先检查仍在运行的旧服务健康，核对目标 main HEAD，构建并检查新 release，再次核对 HEAD；此时才建立维护响应和写控、停止旧服务并等待所有写入者停止。锁内内嵌完成迁移前成套备份及异机复制，不重复取发布锁；成功后由单个执行者迁移，校验版本及结构后才切换应用。数据库迁移锁还须阻止脱离发布流程的重复执行。全程持有发布互斥；不能先停旧服务再调用现有部署入口，否则旧服务健康检查会失败。长耗时或非事务迁移须另行审阅和演练，不能默认可原子回滚。

   外层流程必须把停写开始至验收结束纳入统一失败处理：备份、迁移或进入 `activate()` 前任一步失败，均停止发布，保留原 `current`，重启已确认兼容的旧服务并检查健康。迁移已部分生效时先按事务结果与兼容性判断是否能启动旧版，无法确认则保持维护响应并交人工恢复。现有 `activate()` 不能捕获此前异常。恢复旧服务健康后才解除写控、释放锁，并保留本次发布失败状态。
3. 默认采用先扩展、后收缩：先加兼容表/列，必要时分批回填；暂不删除或重命名旧应用依赖项。新旧版本及两个 worker 并存或先后重启时均须可用。删除旧字段、收紧约束等破坏性变更在旧应用回退窗口关闭后另行发布；无法保持兼容时禁止自动上线，先形成专门维护与恢复方案。

接口交接：
- GET /api/admin/session：200，统一响应 authenticated、admin（id/username 或 null）、csrf_token（或 null）、expires_at（ISO 时间或 null）；匿名不必连接数据库。
- POST /api/admin/login：JSON username/password；成功返回相同会话响应并设置 personal_web_session（Path=/api/admin，host-only）；每次成功发新令牌并撤销当前旧会话。错误账号/密码统一401，不泄露是否存在账号。
- POST /api/admin/logout：需当前会话和写保护；服务端撤销成功后返回匿名会话响应并清Cookie，失败不能在页面伪装已退出。
